# 实际停滞前的绕行学习

本实验接续停车原因反馈与恢复学习目标。目录属于 GitHub `backup` 09:38 快照之后的本地研究。

## 依据与数据

诊断父模型 `early_transfer_bc800_s231015/policy_bc.zip` 的完整18项已安全到达，但 W11 的实际95秒与106秒历史接管均超时。106秒的5种原保护下显式干预也未完成脱困；这些失败动作没有作为正示范。

实际95秒状态的离线实验中，“左转1.6秒、随后请求直行6秒”完整安全到达，总时间114.8秒、行驶10.277米、0碰撞、0保护接管，末端位置误差11.4厘米。请求仅在原掩码允许时执行。专家控制38帧，之后模型控制62帧。另一个左转3.4秒的实验仍超时，负例一并保留。完整源报告在 `../actual_t95_left_physical_20261016/RESULTS.json`。

从完整成功轨迹中仅提取95秒之后、现有恢复分支支持的66条决策。保留原2,355条输入、掩码与标签逐字节一致，以及55条必要停车；新数据共2,421条，没有相同输入的冲突标签。真实物理位姿仅用于验证源轨迹成功，没有进入网络。

`../actual95_learned_validation_20261016/` 已完成6项物理检查。95秒历史接管安全到达，106秒仍超时、170帧全部停车。4项原任务诊断（完整W11、`motion_profile_002`、两个早期转移任务）全部安全到达，与父版的时间、路程完全一致，通过配对限额。4项是专项检查，不能代替完整18项、额外12项、原恢复历史与方向停靠验收。

首条95秒接管已经完成：新模型释放后独立控制100帧，在19.8秒后安全到达，0碰撞、0保护接管；有运动可选却等待从父版109帧减少到2帧。独立检查 [verified_actual95/RESULTS.json](verified_actual95/RESULTS.json) 再次核对了475帧初始化的雷达、里程计、反馈和物理位姿，并用导出的模型重新计算释放后全部100条动作，逐条完全相同。因此本条恢复来自网络，没有在释放后插入专家窗口。该任务已用于监督训练，属于同任务闭环复现，尚非新场景泛化。

新增数据与追加400次优化同时发生，因此不能仅与800次更新的父模型比较就断言收益来自新数据。`../actual95_matched_control_20261016/` 采用同一父权重、Adam状态、种子、学习率和损失，**仅用原2,355条数据，同样追加400次更新**，再检查同一95/106秒历史。该对照的结果未完成前，不进行数据改动的因果归因。

下一项 `../actual95_wait_verified_20261016/` 在完全相同的95秒历史之后，实际执行12帧零速度（2.4秒）作为额外初始化，再分别由新数据模型和匹配训练次数的旧数据模型接管；两者的物理与传感器初始化会再次配对核对。该实验仅在上述4项原任务检查通过后复用主计算槽，不增加第三个物理任务。它检查未用于本次拟合的等待时长，不是106秒故障修复或陌生地图泛化。原排队版本在启动物理仿真前取消，以修正等待时长统计；源码、原计划与取消证据保留在 `../actual95_wait_transfer_20261016/CANCELLATION.json`。

主验证软预算0.35核、硬上限50%；对照依次使用软0.15核、硬上限20%；均为Nice19、单线程。没有新增第三个物理仿真任务。

本次不宣称已解决106秒停车、未见地图泛化、实车定位或部署验收。只有真实闭环表现、原有成功和效率回归共同通过，才考虑后续PPO训练或部署升级。
