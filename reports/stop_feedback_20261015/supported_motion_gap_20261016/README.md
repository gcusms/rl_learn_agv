## 没有被解决的真实停滞

对约束2k的实际 W11 106秒历史后缀解码：模型控制170帧，全部选择并执行停止。动作9（0.01m/s、-0.5rad/s）在170帧均合法；其中168帧只有停止和动作9，另2帧还允许纯右转动作5。首次释放位置误差1.406毫米、航向误差0.02284°；后缀位置误差P95为5.777毫米。雷达与预测输入始终有效，记录的动态接触预测风险始终为0。多数其他动作被激光近场几何组否决，少数帧有投影否决。

因此这段停滞不能简单归因于定位漂移、丢帧或“全部动作被禁止”。同时，动作9合法不代表能脱困；4份现有模型在该释放状态都以极高概率选择停止。证据：`STOP_CAUSES.json` 和同输入回放结果。

## 概率饱和与首项干预结果

`GRADIENTS.json` 使用float64的log-sum-exp计算真实106秒状态的运动概率，避免float32停止概率四舍五入为1。诊断 BC 的运动概率约为`6.982e-9`，相同状态下一百万次采样的期望运动次数仅为0.00698；参考 BC 为`1.223e-8`，两个2k约为`2.3e-9`。这解释了为什么不能指望仅增加少量PPO步数自然试出该动作。报告中的温度8只是假设计算，未应用到模型或运行时，尚无有效恢复证据支撑训练准入。

还用1000/2000步更新前检查点核对了真实保存的rollout，旧动作对数概率最大误差低于`1e-5`。整段250帧的诊断梯度中，联合裁剪因子约0.206～0.587，actor梯度并非处处消失；该计算没有重放实际125帧小批次顺序，不能直接证明critic裁剪是主要根因，也没有据此改变训练器。

106秒的首项0.8秒动作9干预已完整结束：4次请求、3次合法执行，0碰撞，最终仍超时。随后模型执行过左转动作8和4，抵消了部分先前右转；后缀还出现82帧只剩停止。行驶距离仅比未干预增加约1.03厘米，不能当成有效脱困示范。其余两个既定窗口继续按原协议运行，未使用这条失败轨迹训练。
