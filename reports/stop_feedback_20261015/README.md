# 停车原因可见与可行动作学习

目标：解决“策略看不到实际停车原因”及“有可行动作时长期不尝试”。代码与证据归档在交接分支 `progress`；已发布的 `handoff` 快照保留。本实验不更改底盘、12 个动作、速度上限、车体或安全间距。

## 根因与实现

旧 300 维输入虽含上一步停车原因，却只认识旧原因表，`predicted_dynamic_contact` 被合并为 `other`。旧 quality 风险来自地图坐标的轨迹，与保护层里程计坐标的轮廓预测不同。旧恢复训练还依赖固定启用条件，上一轮 2,000 步仅 377 步参与 actor 更新。

新增显式 `stop_decision_feedback_v1` 合同：保留原 300/303 维语义，再追加 136 维；导航 PPO 为 **436 维**，带方向目标的完整推理输入为 **439 维**。新特征包含 12 动作的当前拒绝类别、上一次实际停车原因、同一个保护预测器的 12 动作接触风险（含停止）、扫描年龄、等待时长、有效运动选项数、预测输入有效性与轨迹年龄。新增特征不提供命令、仿真真值或额外障碍物位置。

`SafetyContext` 可选择保存同一次探测的结果，策略和掩码复用这些结果，不重新维护另一套动态预测。原模型默认不开启此抓取，原观测语义保留。主动等候、只剩停止可选、定位/感知保护停车单独记录。新回合与显式重定位清空反馈记忆。

新 PPO 从实车原 2k 检查点初始化；新增输入权重为零，保留原 300 宽计算路径，初始输出保持一致。完整导航 actor 可以更新，不再被旧恢复分支条件排除；仅有停止可选的样本训练 critic，且禁止旧 Adam 动量在此类批次悄悄更新 actor。对原策略在正常开阔场景的非零动作分布施加软约束；原策略偏好停止的样本不受该约束冻结。采样、概率、更新、导出使用同一动作掩码。

奖励仍为原来的真实测地进展、时间、路程、平滑、碰撞与到达项；这次不同时叠加新的等待惩罚。停止动作始终保留，未设置最低前进速度或强制选择非零动作。可行动作只表示通过当前检查，不保证有益或未来安全；动态避让、感知中断和定位不可信时仍需要停车。

## 已有证据及尚未通过的门槛

- 固定横穿失败输入 **58 帧**：新旧 303 维前缀最大差 **0**，未训练动作改变 **0 帧**，新风险与保护层最大浮点差约 **1.84e-8**，上一实际原因逐帧因果正确。[固定回放](frozen_replay/RESULTS.json)
- 功能检查涵盖原因不被折叠、逐动作掩码一致、扫描失效不被当作可靠预测、复位、全 actor 梯度、初始输出、PPO 更新、保存/重载、TorchScript 和方向运行时。它们不计入导航成功率。
- 实际 MuJoCo 训练环境试跑 8 个物理步，436 维观测、当前掩码和执行动作一致；没有 PPO 更新，也没有完成一轮导航。峰值 RSS 约 1.70 GiB、平均 CPU 约 0.35 核。[环境试跑记录](PHYSICS_SMOKE.json)
- 闭环门槛：与原约束候选同任务、同保护，检查到达、碰撞、假到达、超时、共同成功任务的路径/时间与方向停车。单独分析有可行动作时的长等待和仅能停止；等待减少不能抵消碰撞或正常任务退化。

专项初次预算为 **4,000 步**、种子 `221015`，1 个记录过的训练难例回合与 1 个一般任务交替；训练变体与固定开发评估区分。参考基线是上一轮 11/12 的时序定位＋累计轮廓约束候选，此次不合并其他定位变体，以便判断反馈与学习是否改善。

资源：单线程、软平均 0.35 核、systemd 硬上限半个 CPU 核、内存硬上限 4 GiB。PPO 与 MuJoCo 使用 CPU，不占 GPU。步骤完成后自动进行 12 例原/新模型配对评估；候选单独保存，不自动替换部署模型。
