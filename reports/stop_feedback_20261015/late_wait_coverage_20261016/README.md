# 106 秒晚等待状态：训练覆盖审计

审计使用已保存的物理轨迹和原 3,252 条训练输入，不运行新仿真，不改模型、标签、动作许可或保护。审计脚本为 [audit.py](audit.py)，数据和哈希见 [RESULTS.json](RESULTS.json)。

接管后 170 帧恢复头全部启用、全部选择停止。其中 168 帧只有动作 0/9 合法，另外 2 帧合法动作是 0/5/9。2,656 条恢复头启用训练样本中，前一组合没有任何标签，后一组合只有 1 条停止标签。长等待计时已饱和的运动标签只有动作 1/6，没有动作 9；其余状态下虽有 37 条动作 9 标签，不能视为覆盖这里的连续恢复过程。

168 帧的前一执行原因是 `laser_braking_footprint`，另 2 帧是 `policy_wait`。149 帧等待计时达到 5 秒上限。最小原始雷达距离为 0.138–0.177 m，它是雷达到回波的距离，**不是车体安全间隙**。

这些结果支持“当前失败状态与训练分布不匹配”，不能据此认定唯一原因，也不能证明动作 9 在未来持续安全或有任务进展。此前短时合法动作试探未形成完整成功恢复，因此不能把失败轨迹直接标成正例，也不能通过强迫运动或减少保护来宣布修复。

本审计约 2.81 秒，平均约 0.03 个 CPU 核，峰值内存约 49.7 MiB。新增训练更新和 PPO 步数均为 0。后续须验证完整安全恢复，或检查进入该局面的前序可恢复性，再安排针对性微调。
