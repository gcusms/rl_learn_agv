# 原始雷达与里程计输入约定

当前部署原型只输出JSON速度指令，不向实车发送命令。ROS2可以负责发布传感器；导航核心不需要Nav2或行为树。

## 两种输入

`training/run_sensor_navigation.py`默认读取已经对齐的`scan`、`odom`、`velocity`、`timestamp`。可选`--native-scan`模式读取原始扫描和里程计时间序列，进行逐束运动补偿、角度重采样，再交给同一个模型核心。新模式尚未经过真实雷达/底盘闭环验证，不默认开启。

每行JSON为一帧，例如：

```json
{
  "native_scan": {
    "ranges": [2.0, 2.1, 2.2],
    "angle_min": -0.1,
    "angle_increment": 0.1,
    "timestamp": 100.0,
    "time_increment": 0.05,
    "range_min": 0.1,
    "range_max": 12.0
  },
  "odometry_samples": [
    {"timestamp": 100.0, "pose": [0.0, 0.0, 0.0], "velocity": [0.1, 0.0]},
    {"timestamp": 100.1, "pose": [0.01, 0.0, 0.0], "velocity": [0.1, 0.0]}
  ],
  "received_timestamp": 100.15
}
```

这是字段示例；3束扫描不满足当前模型220束、219.44°的覆盖要求，将被拒绝。实际使用驱动发布的完整扫描，缺失回波用`null`，里程计为连续且一致的局部坐标系，不能中途因全局回环直接跳变；全局定位修正需要在定位层处理。雷达坐标轴/安装偏移必须与导出包`hardware.json`一致。

## 时间和补偿

依据ROS2官方[LaserScan消息定义](https://github.com/ros2/common_interfaces/blob/rolling/sensor_msgs/msg/LaserScan.msg)，`header.stamp`是第一束的采集时间，`time_increment`是束间时间；`scan_time`是扫描间隔，不能直接当作束间时间。

参考时间取最后一束：`t_ref = stamp + (N-1)*time_increment`。里程计缓冲向量化插值每束的位姿，保留角度环绕；有限端点转换到同一参考雷达坐标系，再按原生角分辨率保守采样。没有运动时严格保持原有重采样结果。未观测扇区保持未知，不通过插值制造自由空间；不能把当前扫描的所有点当作同一采集时间。

缺少覆盖整个扫描的里程计、时间间隔过大、扫描持续超过0.2秒、帧内位移超过0.1米或转角超过0.2弧度时拒绝该帧并输出停车；这些是当前原型的工程边界，不是实车标定值。`time_increment=0`不会凭空推断扫描周期。错误帧输出停车时同步把模型历史动作记为零，避免下一步仍认为机器人执行了上次运动指令。

`received_timestamp`与采集时间必须来自同一时钟域，实车必须填真实接收/决策时间。离线回放省略它时不能验证真实通信延迟。每帧的里程计样本按时间递增追加，避免重复回放整个旧缓冲。`rear_clearance_known`缺省为false，不应仅因地图后方无墙就填true：静态地图无法证明没有动态障碍。

## 已验证与限制

解析验证包含：平移＋旋转＋非零雷达安装偏移时固定地标对齐、滚动扫描墙面误差、无运动时重采样逐元素一致、航向跨±π的批量里程计插值、缺失位姿/缺失扇区不制造自由空间，以及输入拒绝后历史动作记为停车。真实雷达时间戳、驱动的束间时间、指令积分里程计误差和实际扫描噪声仍需录包核验。

机器人没有新增编码器假设。使用指令积分里程计做补偿可能产生错误，不能代替RF2O/真实运动估计；当前模拟的精确输入测试只证明几何与软件流程，并不证明实车定位精度。摄像头时间同步和融合尚未接入这个适配器。
