# 窄道需求与几何核对（2026-10-13）

用户要求：最窄通道总宽比车身宽 10–15 厘米。无需复杂陷阱脱困训练；普通窄道停车后继续通行仍是必须验证的能力。

## 已核对的尺寸

当前硬件文件配置长 39.39 厘米、宽 32.95 厘米，且 `real_robot_calibrated=false`。实车验收应使用最宽外轮廓（包含轮胎、外壳及突出部件），配置尺寸目前不能替代实测。

## 当前阻碍

`training/neural_navigation/runtime.py` 和课程使用半径 0.30 米的圆形静态膨胀；`StaticMap.free` 还附加栅格余量。上述 42.95–47.95 厘米通道会被当前圆形规划空间排除，不能期望 PPO 通过更多步数学会穿过被规划器禁止的区域。

安全层已按朝向矩形检查，边距每侧 0.04 米。10 厘米总余量仅剩每侧 1 厘米误差预算，还未扣除地图误差、横向定位误差、偏航及动态响应。既有普通场景的定位误差不能直接当作窄道横向误差验收。

先前仅放行局部起点的矩形连接试验未改善 023，反而增加全停车帧；不能直接扩展成窄道运行方案。

## 下一阶段方案

1. 先搭建 15、12.5、10 厘米总余量的直线窄道基准，训练场景与冻结评估场景分开；通过能力按宽度分别报告。
2. 路线可通行性按真实车身与路径朝向检查完整通道和入口，包含连续运动扫掠、栅格误差、定位支持；保留未知占据及原生动作安全检查。机器人只能前后和转向，不能侧移。不能把所有圆形禁区直接改成自由区。
3. 在较宽入口先对齐，再低速居中通过。窄道内按两侧激光距离、目标方向和定位质量控制速度；0.05–0.10 米/秒只作为初始课程范围，需闭环验证。
4. 课程从较宽窄道逐步缩至目标宽度，保留至少一半普通导航任务；不再以复杂围困场景作为主要训练目标。先验证几何与合法动作，再启动针对性 PPO。
5. 奖励使用测地进展、安全到达、平滑动作、适度居中和效率；必要的让行等待不惩罚。墙距目标随通道宽度变化，避免沿用宽场景的近墙惩罚把所有窄道通行都当作坏动作。
6. 验证窄道入口、出口收敛、暂时堵塞后恢复和短时丢帧后继续；碰撞、最小墙距、横向/航向误差、到达率、时间分别统计。15 厘米通过不等于10厘米也通过。

## 当前状态

本文件是需求及几何审核，不是实现完成或训练达标报告。未修改车身尺寸、安全边距或部署模型，也没有启动新的窄道训练。先解决当前规划器无法表达目标窄道的问题，再进行专项训练。精确计算及来源哈希见同名 JSON。
