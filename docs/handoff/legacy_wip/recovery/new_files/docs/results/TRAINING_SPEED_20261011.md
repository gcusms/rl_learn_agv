# 本机训练吞吐检查（2026-10-11）

## 设备与结果

18 核 / 36 线程 Xeon E5-2696 v3，62 GiB 内存，RTX 3060 Laptop GPU（6 GiB）。PyTorch 2.8.0+cu126；沙箱内 CUDA 不可见，沙箱外实际 GPU 运算及 PPO 更新成功。

| 配置 | 短测步数 | 包含采样和 PPO 更新的耗时 | 吞吐 |
|---|---:|---:|---:|
| CPU 8 环境 | 2000 | 19.08 秒 | 104.8 步/秒 |
| CPU 12 环境 | 3000 | 19.45 秒 | 154.3 步/秒 |
| CUDA 8 环境 | 2000 | 20.32 秒 | 98.4 步/秒 |

归档 CPU 4 环境长跑为 58.4 步/秒；其设备不是本机，不能作为严格同机加速比。初次本机 CPU 4 环境测试与 GPU 测试重叠，未纳入公平比较。CPU 8/12 与最终 CUDA 8 测试顺序执行。

## 方法与边界

使用既有 TrainingMission、冻结的 v3 定位/规划及父策略；每环境采样 250 步，batch_size=250，n_epochs=4，四批离线动作辅助更新。测量包含环境采样、推理、PPO 更新；不含进程启动、模型保存和独立评估。每配置只有一个 rollout，不能证明长时间稳定吞吐或模型质量。未导出策略、未覆盖现有模型、未修改训练代码。

增加环境数同时扩大 rollout、降低每条样本对应的辅助更新频率。正式训练需按采样量校准辅助更新比例，并用独立任务比较质量。优先试用 CPU 12 环境、每进程单线程、无渲染；GPU 对当前小型 MLP PPO 没有显示收益。

## 时间预算

保守先按 120–150 步/秒估算：100 万步约 1.9–2.3 小时，300 万步约 5.6–6.9 小时。独立评估、保存、复测另计；多轮修复和多随机种子实验仍需额外时间。性能优化不能保证策略效果，须通过预先固定的成功率、碰撞、路径、耗时和保护触发指标验收。

## 后续优化顺序

1. 适配续训入口及并行参数，建立 12 环境长时吞吐与学习基准。
2. 优化 Python 物理子步计算和静态路线可见性/净空检查，做固定动作回放一致性验证。
3. 保持物理时间步、激光视野、噪声、动作约束和神经路由传播迭代数。
4. 至少三个随机种子检查学习结果，并分别报告静态、动态和传感器异常任务。
