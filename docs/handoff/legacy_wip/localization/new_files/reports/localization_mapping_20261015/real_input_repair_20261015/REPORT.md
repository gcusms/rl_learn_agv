# 实车输入与射线定位优化结果（2026-10-15）

本轮完成了实测轮速＋IMU 的独立输入适配、静态定位的射线路径检查，以及可加载的独立候选包。42 项实现检查通过。固定仿真验证集的位置误差 P95 从 **18.51cm 降到 18.04cm**，改善约 2.5%；不是显著突破，也不能外推为实车精度。

**目前保留为实验候选，不替换原模型、不开始扩大 PPO。** 真实录包没有独立位姿真值；射线检查减少了可接受的地图更新，并增加计算开销。是否因此减少错误配准、是否产生更多等待，需要实车参考点和闭环导航验证。已知地图全局恢复与未知地图 SLAM 的旧失败尚未解决。

## 1. 本轮实际修改

| 部分 | 修改 | 边界 |
|---|---|---|
| 运动输入 | `MeasuredOdometry` 因果融合实测车体 `(vx, vy, wz)` 与 IMU Z 角速度，保留麦轮横向测量，停车连续证据下缓慢估计陀螺偏置 | 不接受指令速度代替运动；不是完整 robot_localization EKF；协方差未标定 |
| 数据连续性 | 检查采集时间、过期/未来测量、非有限值、速度跳变、积分空档；重复帧不重复积分 | 空档后标记连续性丢失，须显式恢复参考；不会默认缺失期间没有移动 |
| 输入适配 | `MeasuredNavigationAdapter` 在运动输入不可用时返回停车且不调用策略 | 显式调用；没有自动接入 ROS 发布器或改变实车运行配置 |
| 静态定位 | `VerifiedStaticLocalizer` 先检查有限雷达射线是否穿过更近的地图占据区；矛盾束不进入静态配准或历史支撑 | 原始扫描继续提供给避障，原地图/车体/4cm 余量保持；未知不当作地图命中 |
| 更新拒绝 | 候选修正若引入过多新的射线矛盾，保留里程计传播，不缩小协方差或保留错误历史 | 阈值是待校准候选，不是安全证明；允许少量采样/地图误差，不是完全无矛盾要求 |
| 运行日志 | 增加矛盾束数、排除的静态命中数和候选新增矛盾数 | 诊断字段增加，actor 观测维数与动作编号保持 |
| 计算 | 只打包每条射线实际需要检查的自由区间 | 保持半格采样和原端点不等式；没有增大步长、删墙或放松接受条件 |

定位使用新显式合同 `ray_consistent_static_tracking_v1`；基础定位合同默认行为保留。回归检查覆盖 Python 与已有原生内核的姿态/协方差一致性及拒绝更新路径。候选默认使用 Python，不要求新增编译。

## 2. 轮反馈、时间与配置核验

录包底盘仍选 `odom_source=command`。1911 条反馈新鲜且有效；用记录中的轮序、符号、轮径和麦轮公式重算车体速度，与反馈中的车体速度最大差为 0。这只证明软件换算一致，不证明轮径/CPR/实际安装已标定。

在有 IMU 的对应区间，轮速转弯方向与陀螺仪 **99.84%** 一致，角速度差 RMSE 约 **0.0488rad/s**。速度命令与轮速的前向差绝对值 P95 约 **0.1346m/s**；因此在启动、停车和响应变化时，不能把速度命令视为真实运动。轮滑依然会影响编码器。

本轮按采集时戳只使用当时已到达时间范围内的 IMU 测量，不插入未来帧。原有 15,820 条轮里程计中，等待两路测量就绪后处理 **15,634 条**，全部通过时效/连续性检查。它们不是 15,634 次导航成功。

| 轻量融合指标 | 本机结果 |
|---|---:|
| 就绪后处理帧 / 有效输出帧 | 15,634 / 15,634 |
| CPU P95 / 最大 | 0.762 / 2.358ms |
| 最后陀螺偏置估计 | 0.0000924rad/s |
| 有独立绝对位置真值 | 否 |

本轮还只读检查了 bag 静态 TF：`base_footprint→base_link→lidar_frame` 合成平移为 `(0.118389, 0, 0.116682537)m`，与模型配置一致；IMU 仅绕 Z 安装旋转，平面 Z 角速度方向相容。**TF 数值一致不证明物理安装或雷达驱动采集时刻已实测校准。** 没有擅自把扫描整体平移一个扫描周期。

已提供 [编码器与 IMU 接入说明](../../../deployment/ros2_recording_adapter/examples/measured_motion/README.md)、底盘参数覆盖及单一 EKF 配置示例。沿用录包的轮径 0.10m、轴距 0.20m、轮距 0.22m。现有 ROS 启动文件已支持 `odom_source:=encoder`；需要从运行参数确认实际生效。没有修改用户正在用的机器人程序或固件。

## 3. 有真值的固定仿真配对回放

共回放 28 条已冻结的 MuJoCo 传感器轨迹，其中 22 条属于原验证划分，合计 2855 帧。两种定位器使用完全相同的扫描、里程计、地图、初值、10m 有效量程；真值仅用于评估，不进入定位器。

这些地图和故障轨迹此前已用于开发，本轮是固定回归集上的机制对照，不称为全新地图泛化或新的闭环导航验收。也没有在这里重新比较 AMCL。

| 验证集指标 | 上一轮 temporal | 本轮射线检查 |
|---|---:|---:|
| 逐帧位置误差 P95 | 18.51cm | **18.04cm** |
| 逐帧航向误差 P95 | 1.526° | **1.368°** |
| 各轨迹终点误差均值 | 3.42cm | **3.27cm** |
| 本机 Python 定位 CPU P95 | **7.88ms** | 14.59ms |
| 本机 Python 定位 CPU 最大 | **13.37ms** | 23.23ms |

以上 P95 按验证帧汇总，终点误差按轨迹平均，不能互相替代。少量长轨迹的弱几何误差仍主导整体 P95。

| 长距离类别 | 原位置误差 P95 | 本轮位置误差 P95 |
|---|---:|---:|
| 单面长墙 | 12.36cm | 12.46cm，略退化 |
| 平行走廊 | 20.33cm | 19.38cm |
| 稀疏非对称区域 | 30.54cm | 30.54cm |
| 有特征进入开放区域 | 18.01cm | 18.01cm |

**射线一致性不能凭空补出沿墙或空旷方向的绝对位置。** 当前结果不满足仅多 10cm 的窄道所需的最坏情况误差预算。

![回归误差与计算开销](comparison.png)

打包计算前，候选的 CPU P95 为 17.98ms；打包后为 14.59ms，下降 **18.85%**，仍慢于原 temporal。73 个前后配对 NPZ 的姿态、标准差、有效性、排除束和运动输出最大差为 **0**；两次运行是实现等价检查，不是两批独立成功样本。没有用计算精度或保护门槛换取速度。

## 4. 真实录包回放：更少接纳不等于更准确

对全部 1516 条决策输入、22 个任务代次做四组对照：原 EKF / 新轮速融合 × temporal / 射线检查。每个代次沿用记录里的人工或默认初值，并非绝对真值；没有跳过任一代次。

| 输入 | 原定位接受扫描帧 | 射线定位接受扫描帧 | 候选因新增射线矛盾拒绝 |
|---|---:|---:|---:|
| 原录制 EKF | 832/1516 | 583/1516 | 46 帧 |
| 实测轮速＋IMU | 830/1516 | 606/1516 | 25 帧 |

静态命中排除数按帧累加，同一物体可重复计数，不能当作发现了多少个动态障碍。拒绝减少不一定更好，拒绝增加也不一定更安全；需要真实位姿才能判断配准正确性，闭环试验才能判断等待和通行率。

**新增拒绝可能加剧等待，这是暂不切换部署的主要原因之一。** 输入已变但 actor 未微调，也可能影响动作分布；权重相同不代表闭环行为完全相同。

| 录包故障段 | 最初已部署模型的估计净位移 | 上一轮 temporal＋原 EKF | 本轮射线＋轮速/IMU |
|---|---:|---:|---:|
| 任务 13，约 2.8s | 约 0.735m | 0.0548m | 0.0521m |
| 任务 19，约 4.2s | 约 1.347m | 0.0248m | 0.0351m |

旧的大幅异常修正主要已由上一轮拒绝弱几何修复压下。本轮保持与测量运动相近的量级，**不能将上轮进展重复归为本轮新增精度改善**，也不能将轮里程计当作物理真值。

前一轮 6 段全图恢复仍无通过确认的证据。本轮没有重跑或放松全图恢复门槛。对前一轮搜索的最高端点候选作射线诊断，任务 7/10/13/19 中很多矛盾来自较大连通占据区及较长穿透段，并非只由孤立噪点造成。[地图与候选扫描叠加](audit/map_scan_candidates.png) 显示的是待核验候选，不是真实机器人位置。不能删掉这些占据区来获得表面成功。

## 5. 可加载的候选包与方向停车

候选：`models/localization_mapping_20261015/ray_consistent_candidate/portable/`。

基础来自上一轮带方向目标的 temporal 候选：actor、router、硬件、12 个动作、303 维观测和方向停车合同逐字节相同。新增的是定位合同与配套软件输入适配，**不是新训练的 actor 或神经定位权重**。模型包约 0.55MiB。

实际加载校验通过 9 个 manifest 文件哈希。对一帧“当前位置相同、目标方向差约 0.5rad”的扫描输入，候选输出 `[vx=0, wz=0.5]`，没有误判为已满足方向目标。这只是单帧方向输入/运行时检查，不证明已完成闭环停车精度验收。

候选默认使用 Python 定位，无新增编译需求。轮速适配必须显式接入，也可在 ROS 中改用现有 EKF 的编码器来源；加载候选本身不会自动切换底盘里程计。所有候选标记 `deployment_approved=false`，原部署模型未替换。

## 6. 接下来必须补足的验证

1. **实车参考点短测。** 在固定起点做已测距离直行、左右转和停车，记录地面参考位置/朝向，比较原指令来源与编码器来源。分别检查距离比例、轮序、航向、反馈年龄和受阻时运动。用自身输出或指令积分作真值都不能证明准确。
2. **地图内新增障碍。** 在几个已测位置静止放入/移走未入图障碍，同时记录原始扫描、轮反馈、IMU、`map→odom`、定位拒绝原因和实际指令发布；核验新增束确实不拉动地图定位，而静态信息恢复后能够继续纠偏。
3. **闭环回归。** 同一已知地图路线配对跑原候选与新候选，覆盖正常导航、窄门、临时堵路、丢帧、原地改朝向和方向停靠。报告物理到达误差、碰撞、等待与最大定位误差，单独统计保护停车和策略等待。
4. **按证据补训。** 输入校准后，将真实丢点/延迟/轮滑分布加入固定课程。仅在可行路径、可信定位下仍存在策略决策问题时补训 actor；静态匹配或路由失败分别处理相应组件。当前没有新增 PPO 步数，也没有后台训练运行。
5. **未知环境单独验收。** 本轮不提供新的在线 SLAM 后端或真实回环约束。历史未知环境失败不能由本轮已知地图回放改善代替，需继续比较子图匹配、里程计退化与回环正确性。

这不是本机 CUDA/内存已经耗尽的表现。本轮主评估平均约 **0.350 核**、峰值 RSS **130MiB**、耗时约 **4分46秒**，单线程低优先级；没有使用 GPU，也没有新增大训练文件。完整小规模试验与报告占用约数 MiB，磁盘仍余约 6.05GiB。定位时间是本机单组件测量，不是 Jetson Orin 的端到端预算。
