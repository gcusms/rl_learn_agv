# Safety-context PPO experiment (2026-10-11)

Objective: expose why the deployed guard stopped/projected an action, and let PPO explore valid alternatives. This is an experimental candidate, not a promotion or a real-robot validation.

## Policy interface

The legacy 235-dimensional sensor observation remains unchanged. The optional `safety_context_v1` contract appends 32 features, for 267 total: 9 full-command feasibility flags, rear visibility, previous normalized proposed action (2), previous normalized executed action (2), override flag, previous reason (16-way one-hot), and fully blocked wait duration / 5 s. Schema, feature order and probe velocities are stored in hardware.json and checked on export/runtime load. Old 235-dimensional bundles continue to use their original interface. Unknown new reasons are represented by `other`.

Probes are (v,w) = (0.2,0), (0.1,0), (0.05,0), (0,0.5), (0,-0.5), (0.1,0.25), (0.1,-0.25), (0.2,0.25), (0.2,-0.25). They check current sensor-based guard feasibility, not future dynamic safety guarantees. No probe becomes an executed command. PPO still chooses v/w; the existing deterministic guard remains the final action transform. No lateral motion, privileged obstacle coordinates, A* runtime or new encoder assumptions were introduced.

The copied near-field memory is transformed once for all probes; independent shallow guard copies retain separate reverse timers and consume the same prepared points. Live memory is never updated by observation probes. Tests compare the results to independently deep-copied real guard checks, including the recorded stall snapshot.

## Learning

Warm start from the safer forecast_directional parent (guarded_parent). Widen actor/critic input layers with zero new columns, retain old weights, and verify deterministic initial mean actions within 2e-6 over 256 inputs (smoke measured 6.26e-7). Optimizer is fresh because dimensions changed. Initial normalized Gaussian std 0.30, floor 0.20 / ceiling 0.50 enforced before rollout collection, entropy coefficient 0.003, learning rate 3e-5, rollout 250 per environment, minibatch 250, 4 epochs, target KL 0.02. Never change std between sampling a rollout and its PPO likelihood update. Existing guarded/geodesic/clearance reward retained; localizer and router frozen.

Main curriculum keeps 60% general robust tasks and rehearses 40% randomized historical training failures. The pool contains 15 failures from actual training episode logs, not development/final manifests. Rehearsal jitters starts/goals by up to 0.10m and headings by up to 0.25rad, generates a fresh scan-noise seed, slightly varies obstacle speed inside 0.08-0.16m/s, and validates free-map endpoints and route reachability. General tasks continue to retain static navigation, slow dynamic profiles, odometry perturbations and dropouts. Exact development cases are evaluated separately; final sealed acceptance is unused.
