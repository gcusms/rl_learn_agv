# 四窗口 MuJoCo 导航实测视频

四个窗口：真实 ROS2 Humble Nav2 NavFn + TEB，追加 PPO 10,000 / 50,000 / 100,000 步的已有检查点。三个 PPO 策略有相同预训练基础；这些数字不是从随机权重起累计训练步数。

已知四房间地图，相同任务种子 31002、四个连续目标点、相同机器人和动作限制（前进 0.20 m/s、转向 0.50 rad/s）。两根实体柱子在机器人接近每个目标时沿物理运动路线进入、停留 8 秒、再离开。运动受墙体、另一柱子和机器人距离约束，不瞬移穿模。激光实际视野 219.44 度、220 束。画面显示真实扫描、规划路线、实际轨迹。

录像使用同一个模拟时间轴，统一 5 倍速。到达判断同时检查定位结果和实际距离，不手动跳目标、不把失败截掉。单次四目标任务不是统计成功率评估。

## 原生基线

Nav2 的 map_server、AMCL、planner_server、controller_server 是实际 ROS2 可执行节点。全局规划器是 NavFn（use_astar=true），局部规划器是上游 TEB Humble 分支插件，算法未替换。

TEB 源码：https://github.com/rst-tu-dortmund/teb_local_planner/tree/humble-devel

此环境下标准激光 ObstacleLayer / TF 更新链路出现停滞。有效录制配置为静态地图加 inflation 全局/局部代价地图，并将真实激光端点通过 TEB 的原生 ObstacleArrayMsg 接口输入局部优化器（近 3 米点、0.12 米采样间距、0.02 米端点半径，剔除已知墙面附近 0.22 米内返回点，与 PPO 的地图融合阈值一致；TEB 最小附加安全距离为 0.06 米）。障碍物坐标由真实 AMCL 位姿和实际部分视野扫描转换，未使用柱子真值或机器人真值。插件接口补丁将实际 ROS TF 消息同步至已有 TF buffer，并增加诊断日志；TEB 轨迹优化算法未修改。这不是未经配置的 Nav2 默认基准。

PPO 窗口使用保存的实际权重、神经激光定位与神经路线规划，以及地图/激光融合处理；机器人运行时不使用 AMCL / A*。场景柱子运动调度可以使用环境真值和静态地图规划，它不是机器人策略输入。

## 数据和重现

每个方法目录保存 trace.json 和 metrics.json，包括逐帧 qpos、qvel、扫描、位姿估计、规划路线和干预记录。comparison_metrics.json 包含最终指标和检查点 SHA256。保留早期故障诊断目录，但这些目录不能作为算法效果结论。

在项目根目录运行 bash training/run_native_comparison.bash 录制 Nav2/TEB；渲染入口 training/render_navigation_comparison.py。ROS 依赖在项目独立目录，未替换系统 ROS。

本次 PPO 实测三个检查点均完成 4/4。1 万步 200.4 秒，5 万步 204.8 秒，10 万步 208.6 秒，均无碰撞。因此本视频不能证明“1 万失败、10 万最快最好”。如需该训练进步结果，需要真实改进训练并在独立测试任务中重新验证。
